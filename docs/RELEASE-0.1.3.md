# Codex 随行 0.1.3

## 重复消息已修正

这次查到的是重复显示，不是重复执行：同一条消息的“本轮输入”和 Codex 原生用户消息被同时列出。现在按消息客户端标识合成一条；原生回显到达时原位替换，不再多出一条。不同轮次、不同消息 ID、真正再次发送的同文消息和追加指示不会误删。

发送、追加、审批、新建和 Fork 在点击时立即锁定。仓库层对同一电脑的重叠操作直接拒绝，不排队生成新操作；不同电脑不互相阻塞。结果不确定时仍保留草稿并禁止自动重发。

## Fork 已加入

打开原会话，点右上角分叉图标“Fork 当前会话”：

- 当前工作区（原目录）：保留历史，新聊天与原聊天共用实际文件。
- 新工作树（worktree）：保留历史，从当前工作区状态创建隔离副本，仅适用于 Git 仓库。

Fork 不会自动发送新指令，不会切换到另一台电脑。原任务运行中或有待办时先等它结束，不会为了 Fork 自动中断。临时会话不支持。

新工作树由电脑 Codex 异步设置，手机显示已提交；准备完成后从该电脑任务列表打开。设置或历史同步未完成时，不把临时 ID 当真实会话，也不自动再次 Fork。上次结果提示持久保留，需在电脑核对后才能清除。

“新建会话”仍是从默认目录或已有项目开始的全新聊天，不带原历史；Fork 与它分开，不容易误操作。

## 更新与安全

使用同签名的 0.1.3 APK 覆盖更新，不要卸载。Windows 换成同版便携包；只重开桥接，不重启 Codex。保留手机数据及 `%LOCALAPPDATA%\CodexRemote`，配对不变。

未修改 Codex 安装包、账号、模型、沙箱或审批配置。当前目录非 Git 仓库时工作树选项会置灰；不会为了让按钮可点而擅自初始化 Git 或创建工作树。

开发验证不向现有聊天发送测试指令，也不擅自 Fork 聊天。Fork 的真实创建端到端和两台物理 PC 联合验收仍未完成；按钮与协议已实现，不把单元测试当作上述验收通过。具体构建与安装结果见 `验证记录.md`。
